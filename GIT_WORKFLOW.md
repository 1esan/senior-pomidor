# Работа с Git

Основная ветка `main` содержит проверенное состояние. Для доработки создавать `codex/<короткое-название>`. Не смешивать изменение поведения с переносом личных данных.

## Обычный цикл

```sh
git switch main
git pull --ff-only
git switch -c codex/task-name
# Изменения и подходящие проверки
git diff
git add <конкретные-файлы>
python3 -B tools/check_repository.py
git diff --cached --stat
git commit -m "Describe the change"
git push -u origin HEAD
```

Потом открыть pull request и объединить после просмотра изменений и проверок. Работа с ветками не создаёт отдельную папку и не запускает приложение. Для изолированной разработки при работающем боте предпочтителен отдельный Git worktree; рабочую ветку работающего процесса не переключать.

## Проверка перед коммитом

Хуки лежат в `.githooks/`. В этой копии включены через `git config core.hooksPath .githooks`. После нового клонирования включить той же командой. Хуки локальные, их можно отключить, поэтому перед отправкой дополнительно проверять индекс:

```sh
python3 -B tools/check_repository.py --all
git status --short
git diff --cached
```

Проверка не печатает найденные значения секретов. Она распознаёт несколько типовых ключей и запрещённых файлов, а при наличии локального профиля дополнительно ищет его контакты. Это дополнительная защита, а не гарантия распознавания любых персональных сведений. Новый файл осматривать перед добавлением.

Не использовать `git add -f` для профиля, сессий, журналов и резервных копий. Не выполнять `git clean -fdx` в рабочей папке: исключённые данные могут быть удалены. Приватный репозиторий не является хранилищем ключей.

## Восстановление

Ошибку исправлять новым коммитом или `git revert`, не переписывать общую историю без отдельного решения. Секрет, попавший в Git, нужно отозвать: удаления из последнего файла недостаточно. Git хранит код, а профиль и рабочее состояние требуют отдельного бэкапа.

Первые исходники зафиксированы как `baseline-2026-10-27`. Старую рабочую версию можно посмотреть по тегу в отдельной копии; не откатывать работающего бота поверх его состояния.
